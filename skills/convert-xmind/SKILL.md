# convert-xmind

## 何时使用

在以下场景使用本技能：

- 用户说「把这章/这篇转成 XMind」「生成 xmind markdown」「做成思维导图」等
- 用户提供或提到 PDF，并希望转为 XMind/思维导图结构
- 用户显式提到使用 `convert-xmind` 技能

输出应是：可以直接粘贴到 XMind 或支持 Markdown 大纲的思维导图工具中的 Markdown 文本。

### 输出文件位置与命名

- 将生成的 XMind Markdown 保存为文件时，与源文件放在同一目录（同层级）。
- 文件名为：原文件名 + `-xmind` 后缀，扩展名保持 `.md`。
  - 示例：源文件为 `AI工程化导论.md` 时，输出文件为 `AI工程化导论-xmind.md`。
  - 示例：源文件为 `chapter1.pdf` 时，输出文件为 `chapter1-xmind.md`（与 PDF 同目录）。
- 若输入为「当前文档」，则用当前文档所在目录与文件名推导输出路径；若为用户指定的 PDF，则用该 PDF 的目录与主文件名推导。

## 输入来源

### 1. 当前文档

- 将用户当前打开的文件内容视为源文本（一般为 Markdown 或普通文本）。
- 直接在该文本基础上识别目录/标题、正文、表格等结构。

### 2. 用户指定 PDF

当用户指定 PDF 路径时：

1. 使用 `pdfplumber` 等工具提取文本内容（示意流程）：  
   - 提示环境中若未安装，可运行 `pip install pdfplumber`。  
   - 逐页提取：`page.extract_text()`，拼接为完整文本。
2. 如有明显的「目录」或章节标题，可通过简单规则/正则识别：  
   - 例如：以“第…章”“第…节”“Chapter” 或特定编号开头的行  
   - 或显式的目录列表（标题 + 页码）
3. 将提取出的正文视为一篇长文，后续统一按「内容处理约束」和「样式处理约束」进行转换。

> 无论源是当前文档还是 PDF，后续所有规则完全一致。

## 转换原则总览

在开始具体步骤前，整体遵守以下原则：

- **结构**：以文档的「目录」为根节点下的二级标题骨架。
- **信息**：尽量保留所有细节知识点，但对**叶子节点的文字**做总结和精炼。
- **语义分层**：遇到同时包含「定义」和「定义解释」的内容，要拆成两层。
- **表格**：使用「按行映射为分支」的方式，将表格转为树状结构。
- **样式**：所有非叶子节点用 Markdown 标题且不缩进；按要求处理星号、序号和图标；去除所有加粗。

## 内容处理约束

### 1. 目录驱动的二级标题结构

- 将思维导图的「根节点」视为文档整体主题（通常对应文档标题或用户给出的主题）。  
- **根节点下的一级子节点**（XMind 中的第二层）对应 Markdown 的**二级标题 `##`**。  
- 这些二级标题必须以文档中的「目录」为准：
  - 若原文有显式目录（章节标题列表），优先使用该目录顺序和命名。
  - 若无显式目录，则根据文中明显的章节/大标题推断出一份「虚拟目录」，用作二级标题。

建议生成结构示意（概念，而非真实输出）：

- 根节点：`# 主题`
  - 目录项 1：`## 目录项 1`
  - 目录项 2：`## 目录项 2`
  - …

### 2. 保留细节，精炼叶子节点

- 拆分或生成树结构时，**不要丢失知识点**（概念、条件、结论、例子等都应在树中有对应节点）。
- 但对于**叶子节点**（没有子节点的节点）：
  - 对原文内容做 **总结、压缩与改写**，避免整段大段复制。
  - 使用简练的短句或要点列出核心信息。
  - 保证叶子节点在单行内尽量完整表达一个知识点。

### 3. 定义与定义解释拆分

当某一段或一句话中同时出现「术语的定义」和「对该定义的进一步解释/说明/举例」时：

- 拆分成两层结构：
  - 父节点：仅包含**定义本身**（术语 + 简洁定义）。
  - 子节点：包含**解释、原因、补充说明或示例**。
- 若原文中包含星号标记（见「样式处理约束」中的星号规则），且该星号对应这段内容，则星号应标记在父节点（定义所在节点）。

示意：

- `## 概念 A`
  - `:label: 概念 A 的定义`（父节点）
    - `:memo: 进一步解释或例子`（子节点）

### 4. 表格的行式映射

当遇到表格时，将其转为树状结构，规则如下：

- **层次结构**：
  - 表格中的**每一行**视为思维导图中的一个分支（一个子主题）。
  - 表格的**列**用于定义该分支的层级和内容。
- **数据映射**：
  - 表格的**标题行**可映射为：
    - 根节点的一个子节点（例如「某某对比表」），或
    - 该部分的一级分支标题。
  - 每一行数据 → 对应的子主题；列 1 通常作为该行分支的标题，列 2/3/… 作为子层级或补充信息。
- 将行内数据拆分为「主属性 + 若干子属性」的形式，保证表格中的每列信息都有去处。

更详细的表格示例可参考同目录下的 `reference.md`。

## 样式处理约束

### 1. 标题与层级

- **非叶子节点一律使用 Markdown 标题语法**：`#`、`##`、`###` 等。
- 标题前面**不要有缩进**（`#` 前不加空格或制表符）。
- 叶子节点可以使用普通行或列表项（如以 `-` 开头），但不要再用标题级别。

### 2. 星号 [★] 标记

- 原文中出现的星号（如 ★、★★）在生成时必须保留：
  - 星号数量保持不变。
  - 星号需用方括号括起来，例如：`[★]`、`[★★]`。
- 若星号标记的是一整段话，而这段话被拆分成一个树结构：
  - 将星号标记放在该树结构的**根节点**（上层节点），子节点不重复放星号。

### 3. 序号格式

- 统一使用中文全角括号序号形式：
  - `（1）`
  - `（2）`
  - `（3）`
  - …
- 若原文使用其他形式的编号（1. / (1) / ① 等），在转换时规范为上述形式。

### 4. 图标（小图标 / Emoji）

- 每个节点**只保留 1 个**最能表达该节点含义的 Markdown 小图标（通常可以用 Emoji 或 `:shortcode:` 形式）。
- 图标放在节点文字**前面**，例如：
  - `:bulb: 概念说明`
  - `:warning: 注意事项`
  - `:bookmark: 关键定义`
- 选择图标时，大致遵循：
  - 概念/定义 → `:bookmark:` 或 `:label:`
  - 提示/注意 → `:warning:` 或 `:exclamation:`
  - 示例/案例 → `:memo:` 或 `:notebook:`
  - 结论/要点 → `:star:` 或保持与原文星号区分清晰

### 5. 去除加粗

- 生成的 Markdown 中**不要保留任何加粗效果**：
  - 不使用 `**文本**` 或 `__文本__`。
  - 如需强调，尽量通过层级（标题/列表）、图标或措辞表达，而非加粗语法。
- 在最终输出前，如果中间步骤曾使用过加粗语法，应将所有 `**`、`__` 去掉。

## 输出流程（操作步骤）

生成 XMind Markdown 时，可按以下顺序进行：

1. **确定输入来源**：当前文档 vs 用户指定 PDF，并将其统一为可处理的纯文本/Markdown。
2. **识别目录与章节**：从原文中抽取/推断目录，建立二级标题骨架。
3. **按章节填充内容**：逐段阅读原文，将内容映射到对应章节下：
   - 拆分出独立知识点。
   - 对叶子节点内容进行总结和精炼。
4. **处理特殊结构**：
   - 对同时含定义和解释的内容进行分层拆分。
   - 对表格按「按行映射为分支」的方式转成节点树。
5. **统一应用样式约束**：
   - 确认所有非叶子节点为标题且无缩进。
   - 正确设置星号 `[★]` 位置与数量。
   - 统一序号为 `（1）（2）…`。
   - 为每个节点选择 1 个最合适的小图标并放在最前。
   - 删除所有加粗语法。
6. **整体检查并输出**：确保结构清晰、层级合理，将完整 XMind Markdown 写入文件。输出文件与源文件同目录，文件名为「原文件名 + `-xmind`」、扩展名 `.md`（例如 `AI工程化导论.md` → `AI工程化导论-xmind.md`）。

## 检查清单

在给用户最终结果前，逐项自查：

- 结构
  - [ ] 根节点下的二级标题是否与文档目录（或推断目录）一致？
  - [ ] 章节与子节点层级是否清晰，避免同级混乱？
- 内容
  - [ ] 是否保留了所有关键知识点，没有明显遗漏？
  - [ ] 所有叶子节点内容是否已经总结/精炼，而不是整段复制？
  - [ ] 同时含定义和解释的段落是否拆分为「定义」+「解释」两层？
  - [ ] 表格是否按行映射为分支，列信息是否合理分配到子节点？
- 样式
  - [ ] 所有非叶子节点是否使用了 Markdown 标题，且标题前无缩进？
  - [ ] 星号 `[★]` 是否保留原始个数，并正确标在对应树结构的根节点？
  - [ ] 序号是否统一为 `（1）（2）（3）…` 的格式？
  - [ ] 每个节点是否只使用了 1 个合适的小图标，并放在文字前？
  - [ ] 生成结果中是否已经完全去除了加粗语法（无 `**` / `__`）？
- 输出文件
  - [ ] 是否已保存到与源文件同目录，且文件名为「原文件名 + `-xmind`」、扩展名为 `.md`？

如以上项均满足，则可以将该 Markdown 视为完成的 XMind 思维导图文本交付给用户。
