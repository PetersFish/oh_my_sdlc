# Objective

Fix the two review-agent blockers for the `modularize-workflow-runtime` change:

1. **Centralized state-write contract violation**: `workflow_runtime/lifecycle.py` directly deletes, writes, and moves active/history run paths in `cmd_cancel_run`, `cmd_advance`, and `cmd_done`. Fix by routing these mutations through `workflow_runtime.state` APIs.

# Learnings

- Source-level tests that inspect for forbidden patterns (e.g., `shutil.rmtree` in `lifecycle.py`) are an effective way to enforce architectural write-boundary contracts that behavior-level tests alone cannot verify.
- Extra-file drift detection requires enumerating actual directory contents and comparing against the governed set — a fixed-list comparison alone cannot detect files it doesn't know about.

# Suggestions

- Consider adding a similar source-level write-ownership check for `dispatch.py` and other higher-level modules to prevent regressions of the centralized state-write contract.
- The `_GOVERNED_RUNTIME_FILES` set is derived from `GOVERNED` at import time. If the governed list changes, the extra-file detection automatically picks up the new expected set — no separate maintenance needed.

# Risks / Follow-Ups

- The extra-file detection only covers `.py` files in `workflow_runtime/`. If non-`.py` files are later added to the governed set, the detection logic should be extended.
