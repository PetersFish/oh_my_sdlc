# Issues

1. **Run-state mutation is not centralized in `workflow_runtime.state`.** The accepted design says `state.py` is the only module that directly writes workflow run-state files, and the spec requires creation/mutation of pointers, active runs, and history runs to route through the state I/O module. `workflow_runtime/lifecycle.py` still directly removes active run directories in `cmd_cancel_run` and directly writes/moves active/history run directories in `cmd_advance` and `cmd_done`. This also contradicts completed task 6.5. Move these mutations behind state-module APIs while preserving behavior.
2. **Template synchronization does not detect extra governed runtime module files.** The spec and tasks require missing, stale, and extra package files to fail read-only checks. `sync_templates.py` uses a fixed `GOVERNED` list and compares only listed files, so an unexpected extra `.py` file under live, canonical, or distributed `workflow_runtime/` trees is ignored. Existing tests cover missing and stale files but not extras. Add executable extra-file drift coverage and make checks/distribution enforce the complete inventory.

# Learnings

- A green regression suite can preserve observable behavior while missing explicit architecture constraints such as write ownership.
- Fixed inventories detect known-file drift but cannot satisfy an extra-file detection contract without enumerating actual tree contents and comparing the resulting sets.

# Suggestions

- Add a focused ownership test or static review check that fails when higher-level runtime modules directly write/move/remove paths under `.ai/workflows/runs/`.
- Add live-to-canonical and canonical-to-distributed tests that inject an unexpected nested runtime module and assert a non-zero drift result naming that path.
