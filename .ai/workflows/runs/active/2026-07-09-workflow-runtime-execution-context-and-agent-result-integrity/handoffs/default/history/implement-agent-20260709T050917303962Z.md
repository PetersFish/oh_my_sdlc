## Issues

- Tightening terminal validation broke 7 pre-existing tests that recorded
  finish-agent evidence under `"default"` without setting the dispatch intent
  slice_id.  These tests were simulating the done state directly without a
  preceding before-dispatch for finish-agent.  Fixed by mirroring what
  before-dispatch records (`evidence.agent_phase.slice_id`).

## Learnings

- The relevant slice for terminal validation cannot come from the finish-agent
  after-dispatch CLI/agent-result inputs because those are not available at
  terminal time.  The dispatch intent (`agent_phase.slice_id`) recorded by the
  preceding before-dispatch is the correct source, with change_id and default
  as fallbacks — mirroring after-dispatch's order minus the transient sources.
- Test helpers that skip before-dispatch must still record the dispatch intent
  slice_id if downstream terminal validation depends on it.

## Suggestions

- Consider having after-dispatch also update `evidence.agent_phase.slice_id` to
  the resolved slice when before-dispatch did not set it, so the relevant slice
  is always resolvable at terminal time even if before-dispatch was skipped.
  This would make the contract more robust but was out of scope for this
  repair.
