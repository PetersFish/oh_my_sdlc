## Issues

- Python 3.14 `dataclasses` module failed when the module was loaded via `importlib.util.spec_from_file_location` (the test's `_import_module()` helper) because the module was not registered in `sys.modules`, causing `cls.__module__` lookup to return `None`. This broke the `@dataclass` decorator with `from __future__ import annotations` string annotations.
- Review blocker `review_change_set_mismatch`: the first implementation pass recorded plan-checkbox and verification evidence that did not match the live worktree state. The worktree had the plan diff missing and the smoke-test `.skill-install.json` churn present, contradicting the handoff.

## Learnings

- Replaced the `@dataclass` with a plain class using `__init__` with default parameters. This avoids the `sys.modules` lookup issue entirely and is fully compatible with the test's `importlib` loading pattern. The plain class has the same public API (`workflows`, `agents`, `skills`, `full`, `skipped_paths`, `reason` fields + `to_report()` method).
- Plan checkbox edits and verification commands must be performed and re-confirmed inside the implementation worktree, not the main checkout, so the live change set under review matches the handoff contract. Re-running `check_plan_checkboxes.py` in the worktree (not just the main repo) is required for consistent evidence.
- Smoke-test generated `.skill-install.json` churn records transient worktree absolute paths in `source_repo`/`target` fields. Revert or avoid retaining these as part of the change set unless the derived-artifact contract explicitly accepts those path changes. In revision 2 the churn was no longer present.

## Suggestions

- When adding new modules that tests load via `importlib.util.spec_from_file_location`, prefer plain classes or register the module in `sys.modules` before `exec_module`. The `@dataclass` decorator with string annotations assumes the module is in `sys.modules`, which `importlib` loading does not guarantee.
- When smoke-testing incremental sync against a real skill, run it in a throwaway fixture or revert the generated `.skill-install.json` files afterward so the worktree change set stays minimal and free of transient worktree-path metadata.
- Normalize full-regression reporting so the handoff, orchestration summary, and review all agree on whether broad regression passed or had accepted/pre-existing failures. State the exact counts and the single failing test name/id.
