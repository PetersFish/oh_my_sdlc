## Objective

Implement the OpenSpec repair `repair-workflow-decision-block-unlock`: when a workflow branch decision is missing or invalid and the run is blocked, recording a corrected valid `branch_finish_decision` through `record-context` must reconcile the stale block — setting status to `running` and clearing the block — so normal guarded dispatch/advance can proceed. Unrelated blocks and invalid corrections must be preserved.

## Learnings

- The `finish-agent` agent is exempt from the `run_is_blocked` guard at `cmd_before_dispatch` line 2051 (`agent not in {"finish-agent", "finish_agent"}`). This means the dispatch test (task 1.2) passes even without the fix because finish-agent bypasses the blocked-state guard. The real reconciliation test is task 1.1 — asserting the state itself transitions to `running` with `block: None` after `record-context`.
- Block recognition based on structured `type` + `next_allowed` (not message substring) correctly distinguishes the runtime-owned branch-decision block from other `user_decision_required` blocks like the lightweight-flow confirmation block.

## Suggestions

- Consider adding a runtime-owned block `reason` or `gate_id` field to the block structure for even more precise identification, rather than relying on `next_allowed` containing `ask_user_branch_finish_decision`. The current approach works but a structured identifier would be more robust against future `next_allowed` changes.
