## Work Completed

### Blocker 1: Commit-chain invariant (state.py)
Replaced the incorrect "base_ref must equal every dependency's accepted_head_ref" model with the spec-correct "base_ref must equal the **latest** completed dependency's accepted_head_ref (the previous accepted sequential head)". Earlier dependencies' accepted heads are ancestors of the latest head; they need not equal `base_ref`. Removed the `commit_chain_unsatisfiable` error for differing dep heads — differing heads are valid in a sequential chain. The `commit_chain_violation` error is now raised only when `base_ref` does not match the last completed dependency in declaration order.

### Blocker 2: Linked worktree Git validation (dispatch.py)
Replaced `os.path.isdir(os.path.join(root, ".git"))` with a new `_is_git_repo()` helper that uses `git rev-parse --git-dir` to detect repository validity. This works for both normal checkouts (`.git` is a directory) and linked worktrees (`.git` is a file pointing at the real gitdir).

### Blocker 3: Exact ordered commit_refs range equality (dispatch.py)
Replaced the per-commit-ref membership check (each ref within base..head) with an exact ordered range equality check. The supplied `commit_refs` are normalized to full SHAs via `git rev-parse` and compared against the authoritative `git rev-list --reverse base..head` output. A partial list (e.g. `[head]` when `mid` exists) or a reordered list is now rejected.

### Blocker 4: Template sync (canonical + distributed)
Ran `python3 skills/sdlc-project-bootstrap/scripts/sync_templates.py --root .` to sync live `.ai/workflows/scripts/workflow_runtime/state.py` and `dispatch.py` to canonical `skills/sdlc-project-bootstrap/templates/workflow/workflow_runtime/`. Then ran `--distribute` to push to `.opencode/`, `.claude/`, and `.cursor/` distributed copies. Both `--check` and `--check-distributed` now pass.

### Test updates

## Learnings

- The sequential commit-chain invariant is about the **latest** accepted sequential head, not all dependency heads. Earlier dependencies' heads are ancestors of the latest head in a contiguous chain.
- Detecting `.git` by directory shape is not worktree-safe; `git rev-parse --git-dir` works for both normal and linked worktrees.
- Per-element range membership is weaker than exact ordered range equality. `git rev-list --reverse base..head` provides the authoritative ordered range.
- A green full test suite does not compensate for behavior tests that encode the wrong commit-chain model.
