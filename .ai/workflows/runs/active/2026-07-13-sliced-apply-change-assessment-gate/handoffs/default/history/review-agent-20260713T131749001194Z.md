## Issues

### Blocking: `not_required` persisted state is not validated

Spec invariant 7 requires `not_required` to always have a non-empty reason and a governed default slice. The current `validate_implementation_state()` validates status and decision vocabulary, but does not enforce the explicit-waiver invariants:

- `slicing_assessment.status == "not_required"` must have `decision == "single_slice"`;
- `assessed_by` must be non-empty;
- `reasons` must contain at least one non-empty reason;
- exactly one required slice must exist;
- that slice must be `slice_id == "default"`.

Because `cmd_before_dispatch()` also does not validate the complete implementation block before accepting an active `not_required` state, a malformed active state with `status=not_required`, empty reasons, and a pending default slice can still dispatch `implement-agent --slice-id default`. This violates invariant 7 and weakens invariant 12 by allowing historical/invalid compatibility-shaped state to authorize active dispatch.

Recommended fix: add explicit `not_required` validation inside `validate_implementation_state()` and ensure active dispatch paths reject invalid implementation state before slice selection. Add behavior tests that directly construct malformed `not_required` states and prove dispatch/slice-next fail for empty reasons, whitespace-only reasons, empty `assessed_by`, wrong decision, no default slice, multiple slices, and non-default slice id.

## Learnings

## Suggestions

- Treat the plan's malformed waiver cases as required executable regression tests, not only constructor assertions.
- Consider validating implementation state in `cmd_before_dispatch()` before slice selection for all active apply runs whose assessment status is `completed` or `not_required`.
