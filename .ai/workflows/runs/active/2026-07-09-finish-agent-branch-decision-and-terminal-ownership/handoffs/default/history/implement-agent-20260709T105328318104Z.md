## Learnings

- The exit criteria / evidence key validation has multiple code paths (`_check_exit_criteria`, `_missing_exit_criteria`, `_missing_phase_evidence_keys`, `cmd_complete_phase`). All four needed the backward-compat alias to keep legacy runs readable during migration.
- The `_archive_lightweight_superpowers_artifacts` helper derives archive destinations from the runtime design artifact contract (`primary_design_path` + `design_artifact_paths[]`) when finish-agent does not report explicit paths, with collision handling via deterministic suffix.

## Suggestions

- Consider consolidating the four exit-criteria/evidence-key validation paths into a single helper to reduce alias maintenance surface.
- The archive move helper could be extended to record a runtime evidence entry (not just update agent evidence) so the move is observable even without inspecting agent_results.

## Risks/Follow-Ups

- Memory sync target ref rules (Spec Decision 7) are documented in the spec and prompts but not yet enforced by runtime code — they depend on finish-agent recording `memory_sync.target_ref_type` etc. during post_archive_actions. This is a prompt-level contract, not a runtime gate.
- Branch action execution semantics (merge_local, create_pr, keep_branch, discard) are governed by the gate and documented in prompts; the runtime validates the decision value but does not execute the branch action itself (that is finish-agent's job via `finishing-a-development-branch`).
