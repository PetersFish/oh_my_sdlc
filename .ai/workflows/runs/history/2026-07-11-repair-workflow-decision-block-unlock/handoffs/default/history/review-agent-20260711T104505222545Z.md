## Issues

1. **Live change-set mismatch.** The implement-agent artifact declares seven changed files, but live Git also contains tracked changes to roadmap state, `.ai/workflows/runs/current.json`, canonical and distributed `dev-orchestrator` agent files, and agent install manifests, plus untracked workflow-run artifacts and the remaining OpenSpec artifacts. The handoff explicitly says the implement-agent repaired agent drift, yet those agent files are omitted from `changed_files`. The review scope therefore cannot be reconciled with the handoff (`review_change_set_mismatch`).
2. **Unrelated context writes can incorrectly clear the decision block.** `_should_reconcile_branch_decision_block(state, tentative_context)` checks only that the tentative context resolves to a valid decision; `cmd_record_context` calls it for every key. If a stale decision block coexists with an already-valid `context.branch_finish_decision`, recording any unrelated context key transitions the run to `running` and clears the block. The contract requires reconciliation when a corrected valid `branch_finish_decision` is recorded. No test covers an unrelated key write with an existing valid decision. Pass the recorded key into the predicate (or guard in `cmd_record_context`) and add a behavioral regression proving unrelated writes preserve the block.

## Learnings

- The negative tests cover unrelated block types, but not unrelated `record-context` keys against the target block type; this allowed the key-agnostic reconciliation path to pass.
- Derived drift repair performed during implementation must be included in the structured changed-file artifact even when the drift was pre-existing, because it changes the live review scope.

## Suggestions

- Generate `artifacts.changed_files` directly from final live Git discovery after all sync/repair commands, rather than maintaining it manually.
- Add a test matrix dimension for the recorded context key, not only decision value and block type.
