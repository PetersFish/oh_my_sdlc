## Issues

- The first RED run of `test_finish_agent_success_with_missing_expected_artifacts_blocks`
  used `assertEqual(data["status"], "blocked")`, which failed because the
  after-dispatch transition convention keeps `transition["status"]` mirroring
  the agent's own status ("success") while signalling blocking via
  `workflow_command: "workflow.py block"` and `state["status"]: "blocked"`
  (confirmed by the existing `premature_cleanup_evidence` test).  Corrected the
  test to assert on `workflow_command`, `state.status`, and the flipped
  evidence — the behavior assertion is stronger, not weaker.

## Learnings

- The after-dispatch transition envelope reports the *agent* status in
  `transition["status"]`; runtime block state is surfaced through
  `workflow_command`, `blockers[]`, and `state["status"]`.  New blocker tests
  should assert on those fields, not on `transition["status"]`.
- The archive helper's source/destination derivation now has a single
  `_archive_dst_for()` path used for both explicit and contract-derived
  sources, which made adding the counterpart fallback a localized change.

## Suggestions

- Consider an explicit runtime evidence entry (not just agent evidence) for the
  archive move so the move is observable without inspecting `agent_results`.
- The counterpart fallback currently matches by filename equality; if future
  runs use divergent plan/spec slugs, the fallback may need a looser match, but
  Spec Decision 11 pins deterministic slug/date matching as the last resort, so
  filename equality is the intended contract.
