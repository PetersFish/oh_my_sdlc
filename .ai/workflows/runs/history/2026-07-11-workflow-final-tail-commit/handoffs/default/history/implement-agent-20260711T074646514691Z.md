## Assumptions

- `git status --porcelain -uall` is available on the target git version (confirmed on macOS with git 2.x+).
- The `final-commit` command is called after the run is already in history with `status: done` or `current_phase: done`.
- The `--push` flag uses `git push origin HEAD` to push the current branch to the origin remote.
- The user-confirmed policy `exclude_ai_runtime_paths_from_change_set_review` excludes all paths matching `.ai/workflows/runs/**` from review change-set scope.

## Risks/Follow-Ups

- The push test creates a temporary bare repo in the parent of the temp directory; if the parent directory is not writable, the test may fail. This is a test-only concern.
- The allowlist includes `.ai/roadmap/`, `.ai/memory/`, `openspec/changes/archive/`, and `docs/superpowers/archive/` — if future governance artifacts are stored in new locations, the allowlist may need updating.

## Issues

- Initial implementation had a bug where `_run_git` stripped stdout, causing `git status --porcelain` first-line parsing to lose the leading space and shift path characters. Fixed by not stripping stdout in `_run_git` and handling per-line parsing in `_git_status_porcelain`.
- Untracked directories collapsed to directory entries in default `git status --porcelain` output. Fixed by using `-uall` flag to list individual untracked files.
- Review-blocker remediation: prior handoff omitted explicit `verification_passed: true` and had an incomplete change-set that did not account for runtime artifacts created after the initial handoff. Fixed in this revision by re-running verification and refreshing the change-set from live Git with the user-confirmed exclusion policy.

## Learnings

- When parsing `git status --porcelain` output, never strip the full stdout — the leading space on the first line is significant for the XY status code format.
- Using `git status --porcelain -uall` ensures untracked files are listed individually rather than as collapsed directories, which is essential for accurate allowlist classification.
- Narrative verification results are not a substitute for the required structured `verification_passed: true` gate field.
- Workflow runtime state and history artifacts can be created after the implement-agent handoff; the final change-set evidence must be refreshed immediately before review dispatch and must explicitly declare the exclusion policy for runtime paths.

## Suggestions

- Consider adding a `--dry-run` flag to `final-commit` that reports what would be staged without actually staging or committing, for safer pre-commit inspection.
- Consider adding the allowlist paths to the workflow definition YAML so they are configurable per-workflow rather than hardcoded.
- Have dev-orchestrator refresh `changed_files` from live Git after recording the implement-agent result and before dispatching review-agent, and carry forward the runtime-path exclusion policy explicitly.
