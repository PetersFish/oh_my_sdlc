## Issues

- The plan's legacy repair test expected `advance` to work for the final step, but `advance` checks `is_phase_complete(state, "done")` which fails because `done` is terminal and not in `completed_phases`. Used `done` command instead.
- The plan's `post_archive_actions` evidence keys include `post_hook_dirty_tree: false`, which required fixing `_missing_phase_evidence_keys` and `cmd_complete_phase` to treat boolean `False` as a valid evidence value (not empty/missing).

## Learnings

- Boolean `False` is a legitimate evidence value for cleanup indicators (e.g., `post_hook_dirty_tree: false` means clean tree). Evidence validation should only treat `None` and empty string `""` as missing, not `False`.
- When `advance` moves to `done` and blocks on pending hooks, `complete-hook` needs to clear the `hook_blocked` block so subsequent `done`/`advance` commands can proceed.

## Suggestions

- Consider renaming `post_hook_dirty_tree` to `cleanup_dirty_tree` or `generated_files_remaining` in a future change to decouple from the legacy hook terminology.
- The old finish-agent sections (Workflow Cleanup, Commit/Push Checkpoints) should be updated or removed in a follow-up to avoid having two conflicting descriptions of cleanup work.
