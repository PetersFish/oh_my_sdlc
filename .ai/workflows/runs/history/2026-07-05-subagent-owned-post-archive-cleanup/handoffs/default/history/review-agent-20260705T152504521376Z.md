## Issues

1. `post_archive_actions` cleanup booleans can be false while the phase still passes. The spec and finish-agent contract require successful cleanup evidence such as `memory_sync_done: true`, `roadmap_done_checked: true`, and `derived_artifacts_synced: true`. The runtime now accepts any boolean `False` as a present phase evidence key in `_missing_phase_evidence_keys` and `cmd_complete_phase` so that `post_hook_dirty_tree: false` can represent a clean tree. However, the change is global: a finish-agent result with `memory_sync_done: false`, `roadmap_done_checked: false`, `derived_artifacts_synced: false`, `post_hook_dirty_tree: false`, and `cleanup_complete: true` would satisfy required evidence keys, and `cleanup_complete` alone satisfies the exit criterion. This weakens acceptance criteria 3-4 and can mark cleanup complete even when required memory/roadmap/derived cleanup explicitly failed or was not done.

## Learnings

- The previous broad falsy-value rejection was too strict for `post_hook_dirty_tree: false`, but replacing it with global false acceptance is too permissive for success booleans.
- The current tests cover `cleanup_complete: false` as a blocker and `post_hook_dirty_tree: false` as valid evidence, but they do not cover false values for the required positive cleanup evidence keys.

## Suggestions

- Make evidence-key validation distinguish positive required booleans from negative-state evidence. For this contract, `post_hook_dirty_tree: false` should be accepted, while `memory_sync_done`, `roadmap_done_checked`, `derived_artifacts_synced`, and `cleanup_complete` should require `true`.
- Add an executable workflow regression where finish-agent returns `cleanup_complete: true` but one positive cleanup evidence key is `false`; `after-dispatch` and/or `complete-phase` should block.
