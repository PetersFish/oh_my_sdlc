## Learnings

- Terminal evidence validation required updating 7 pre-existing tests that
  set up done states without finish-agent evidence.  The new behavior is
  intentional per Spec Decision 9 — these tests now include finish-agent
  evidence in `agent_results`.
- The roadmap_item test helper needed `context.change_id` set explicitly
  because `start` with `roadmap_item` subject does not set `change_id` in
  context (only `spec_change` does).

## Suggestions

- Consider adding a convenience helper in workflow.py for recording
  finish-agent evidence to reduce boilerplate in tests and real workflows.
- The `current.json` pointer modification during workflow runs should be
  handled by the finish/cleanup phase to avoid dirtying the worktree.

## Risks/Follow-Ups

- The terminal validation only checks `agent_results[slice][finish-agent]`
  with `status=success`.  A failed finish-agent that was retried
  successfully will have the latest success, but a failed finish-agent as
  the latest record would block.  This matches the spec intent.
- `review-agent` and `finish-agent` prompt updates for runtime_context
  preference were deferred (the spec mentions them but the existing prompts
  already cover worktree-mode protocols).  These can be addressed in a
  follow-up if needed.
